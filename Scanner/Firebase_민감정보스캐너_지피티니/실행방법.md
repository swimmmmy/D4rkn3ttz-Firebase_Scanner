# 실행방법

## 가장 빠른 실행

1. 배포 ZIP을 새 폴더에 압축 해제합니다.
2. `실행.bat`을 더블클릭합니다.
3. 본인이 소유하거나 명시적 허가를 받은 대상인지 확인합니다.
4. Wizard에서 Scope 파일을 생성하거나 선택합니다.
5. 대상 URL과 허용 Firebase 경로를 확인합니다.
6. 점검을 실행합니다.
7. `reports/<RUN-ID>/report.html`을 엽니다.

Portable EXE:

```powershell
.\FirebaseSecurityAuditor.exe version
.\FirebaseSecurityAuditor.exe self-check
.\FirebaseSecurityAuditor.exe discover --file .\app.js --offline --output .\reports
```

소스 설치:

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\설치.ps1
.\실행.ps1
```

## Scope 작성

`config/scope.example.yml`을 참고합니다. 승인 reference·승인자·timezone이 있는 만료일, 정확한 origin, Project ID, RTDB URL, Firestore path, Storage prefix/object, cross-origin asset origin을 명시합니다. wildcard와 `*` path는 금지됩니다. RTDB root shallow는 `allow_root_shallow_probe: true`일 때만 수행됩니다. Private target은 Scope 설정, `--allow-private-targets`, `--ack-authorized`의 3중 승인이 필요합니다.

```powershell
.\실행.ps1 validate-scope --scope .\config\scope.local.yml
.\실행.ps1 scan --url https://authorized.example --scope .\config\scope.local.yml --ack-authorized --output .\reports
```

비인증 검사는 Authorization header 없이 수행합니다. 테스트 사용자 A/B는 token 원문을 YAML이나 CLI 인수에 넣지 않고 `FSA_TEST_USER_A_ID_TOKEN`, `FSA_TEST_USER_A_UID` 같은 환경변수와 `config/auth-fixtures.example.yml`을 사용합니다.

```powershell
.\실행.ps1 scan --url https://authorized.example --scope .\config\scope.local.yml --ack-authorized --auth-fixtures .\config\auth-fixtures.example.yml --output .\reports
```

Rules:

```powershell
.\설치.ps1 -IncludeEmulator
.\실행.ps1 analyze-rules --rules-dir C:\authorized-project\firebase --output .\reports
.\실행.ps1 test-rules --rules-dir .\app\tests\emulator --fixtures .\config\auth-fixtures.example.yml --local-test-mode --use-emulator
```

정적 분석은 잠재 위험을 찾고 Emulator는 합성 데이터의 예상/실제 권한 행렬을 검증합니다. 운영 Firebase에는 write 검증을 하지 않습니다.

공유 가능: `summary.md`, `report.html`, 마스킹된 `report.json`, salt로 익명화된 `research-summary.csv`.

공유 금지: `scope.local.yml`, token 파일, 서비스 계정 키, 개인 환경변수, raw debug 로그. 이 도구는 raw response를 생성하지 않습니다.

문제 발생 시 `문제해결.md`를 확인합니다. `BLOCKED_ENVIRONMENT`는 취약하지 않다는 뜻이 아니라 해당 검증을 실행할 환경 의존성이 없다는 뜻입니다.
