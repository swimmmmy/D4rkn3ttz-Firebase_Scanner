# 결과 해석 가이드

- Firebase SDK, `firebaseConfig`, Project ID, Firebase Web API Key 발견은 INFO입니다. Web API Key는 클라이언트 식별값이며 서비스 계정 private key나 ID token과 다릅니다.
- Firebase ID token은 사용자 인증정보이고 Security Rules가 데이터 read/write를 결정합니다. App Check는 앱 요청의 추가 신호이며 Rules의 대체물이 아닙니다.
- RTDB `200 null`은 요청이 허용됐지만 값이 비었거나 경로가 없다는 뜻입니다. 안전 판정이 아닙니다.
- 401/403과 Firebase permission-denied payload는 접근 거부입니다. Firestore invalid query, missing index, precondition 오류는 권한 결과와 분리합니다.
- Storage LIST와 GET은 서로 다른 권한입니다. 하나의 결과로 다른 권한을 추정하지 않습니다.
- Passive mode는 Security Rules가 적용되는 제한된 client read를 검사합니다. Owner mode의 관리자 read는 Rules 취약점 증거가 아닙니다.
- 정적 Rules finding은 코드상 잠재 위험입니다. Emulator expected/actual 일치 결과가 더 높은 confidence를 가집니다.
- HIGH/CRITICAL은 먼저 접근을 차단하고 token/private key가 포함되면 폐기·회전한 뒤 Emulator 회귀 테스트를 수행합니다.
- `CONFIRMED`는 실제 bounded read 또는 Emulator 결과, `POTENTIAL`은 정적 분석, `INCONCLUSIVE`는 환경·parser·network가 결론을 막은 상태입니다.
- 공개 의도가 불명확하면 `manual_review_required`를 확인하고 앱의 공개 데이터 계약과 비교합니다.
